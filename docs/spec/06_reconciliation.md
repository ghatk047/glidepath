# 06 · Reconciliation of the three models

Inconsistencies found between baseline v0.1, levers v0.3 and corporate v0.1, and how the unified model resolves each. Impact = unified default minus v0.3 for scenario C Balanced unless stated. Parity mode (reference/run_tests.py) reproduces the v0.3 numbers exactly by pinning the old values.

| id | area | severity | finding | resolution | impact |
|---|---|---|---|---|---|
| R01 | Units | medium | Baseline stores money in $; levers and corporate in $M. | Engine works in $M everywhere. Seed converts baseline lines on load. | none |
| R02 | Pools | high | Levers v0.3 hard-codes pool sizes on its Baseline tab ('aligned to cost-baseline v0.1') instead of reading the 415 lines. Small drifts: US labour 398.10 vs 398.01, SI 121.18 vs 121.24, DC 37.00 vs 36.99, network 31.50 vs 31.54, other 8.00 vs 8.02. Any edit to a baseline line would not reach the levers. | Pools are SUMs of line items (base.pool_outlay). Sub-pool splits the levers need (Microsoft share, maintenance vs colo) are inputs expressed as shares of the pool. | net +$0.1M |
| R03 | Vendors | medium | Preferred SI book differs: baseline Vendors tab DXC 25 / Cognizant 18 / IBM 15 / #6 12 / Coforge 8 / Infosys 5 = $83M; levers DXC 25 / IBM 18 / Cognizant 15 / #6 14 / Coforge 8 / Infosys 5 = $85M. Long tail $38.2M vs $36.2M. | Baseline is the system of record for spend: vendor.book uses the baseline figures. DXC and Infosys are user figures in both. | lever 7 +$0.05M |
| R04 | Opex vs capex | high | Levers use flat capex shares per lever (US labour 17%, SI 10%, end-user 60%, GCC 0%) while the baseline has line-level capex (US 14.9%, GCC 14.3%, SI 14.1%, end-user 67.5%, DC 62.4%; total $123.9M). | Each lever's saving is split by the pools it touches (lev.eff) and each pool's capex share from the lines. Lever 12 keeps its explicit rule (refresh deferral is capex, TPM and colo are opex). | CY27 opex savings -$2.8M, capex +$2.9M; EBITDA -$2.7M; EPS -$0.003; share price -$0.03. Net outlay unchanged. |
| R05 | DC & hardware | low | Hardware capex outlay: levers $25.0M vs baseline capex lines $23.1M. | Taken from baseline lines (lv.dc_capex). | lever 12 -$0.15M run-rate |
| R06 | Contractor rates | low | Billable hours: baseline 1,880 (H) vs levers 1,900. | 1,880 hours with hourly rates restated ($101.06 onshore, $31.38 offshore) so cost per FTE is unchanged ($0.19M, $0.059M). | none |
| R07 | Workforce | low | US IT attrition: levers 9% vs baseline 8%. | 9% kept: only the levers use it (lever 5). Baseline value was not used in any formula. | none |
| R08 | Duplicate inputs | medium | IT capex life appears twice (levers dep_life, corporate it_life); the CIO target appears three times (levers target, levers Org_Map total, baseline Assumptions). | One variable each: g.it_dep_life, g.target_net (VP split reads res.target). | none |
| R09 | VP targets | high | Two different VP target sets circulate: baseline 17.1 / 15.2 / 11.4 / 56.2 (chargeback off) and levers 24.6 / 22.7 / 15.2 / 37.6 (chargeback on). Same proportional rule, different allocation basis. | One formula with g.chargeback_on. Default on (user: shared infrastructure credited back by usage). Both sets are reproduced in the parity tests. | none (documented) |
| R10 | Org map hand-off | medium | org_map_used.json labels proportional targets as 'equal_target_musd', and the levers read VP shares from a 4-decimal rounded JSON copy of the baseline Org_Map, so org edits in one model did not reach the other. | VP shares computed live from line items x org.dom_share. | VP figures move by < $0.05M |
| R11 | VP allocation | medium | Each lever is allocated to VPs by one key, even when it moves cost between pools (relocation adds GCC cost but is allocated on the SI split). The 'Apps' key is an SI-split proxy. | Kept as default for continuity (g.vp_alloc_method = 1). Method 2 allocates each pool effect by that pool's ownership. | none by default |
| R12 | Corporate link | high | Corporate IT inputs are static copies of pnl_feed. risk27 is a stale hard-code computed with all one-time costs on IT (ot_out = 0). In the spec JSON net27 holds company cash (99.63) while the workbook label says IT outlay and its feed mapping uses cash27 (119.16). | Live link: it.* nodes read pnl.* for the active scenario. Risk factor = confidence-weighted gross / gross, computed live. Scenario picker it_scen replaced by the active scenario plus corp.it_override for custom values. | none at defaults |
| R13 | P&L line split | low | Corporate assumes 30% of IT opex savings land in salaries, wages and benefits. From the lever pool effects the share is 12% in C: SI and contractor savings are not AA employee cost, and GCC backfill adds employee cost. | Derived by default (corp.it_swb_mode = 1); manual 30% still available. | moves ~$22M from SWB to other opex in the P&L; EBITDA and EPS unchanged |
| R14 | Sign convention | low | pnl_feed one-time costs are negative; corporate ot27 is positive. | All savings and costs are positive magnitudes; P&L nodes apply the sign. | none |
| R15 | One-time timing | low | ot_exp below 100% made the non-expensed share disappear from both P&L and cash. | Renamed g.ot_in_year: the share not incurred in CY27 is treated as pre-funded in CY26, outside both tests. Default 100%. | none |
| R16 | Hidden constants | medium | 17 numbers were hard-coded inside lever formulas (one-time cost % for levers 1, 2, 7, 8, 10, 12-16; relocation severance 0.5x; hiring cost $10K; AI setup $1M; FinOps setup $0.5M; TPM saving 40%; app-retirement split 50% software / 30% cloud). | All promoted to inputs (kind = estimate). | none |
| R17 | Lever overlap | low | Lever 16 (invoice audit) runs on pre-lever DC, network and end-user pools and includes locked platform fees. Lever 17 (cost-increase containment) applies avoided growth to the full pre-lever pools. | Kept for parity, documented. Invoice audit legitimately covers locked contracts. Lever 17's overstatement on already-removed spend roughly offsets the understatement from measuring cuts in CY26 dollars (a cut also avoids that spend's CY27 growth). A residual-basis option is a candidate for v1.1. | < $1M either way |
| R18 | Contractor headcount | high | Baseline scales only long-tail and staff-aug lines with contractor headcount; levers cost all 800 contractors at T&M rates and treat managed services as the residual. Large headcount changes can push managed services negative. The baseline Vendors tab also models ~901 preferred-SI FTEs (incl. offshore delivery) against '800 contractors'. | Range narrowed to 500-1,100 and validation rule VR05 (managed services >= 0). Interpretation: 800 = badged contractors; SI delivery-centre staff are not counted. Flag for AA validation. | none at defaults |
| R19 | Lever hooks | medium | Baseline 'Lever hook' column is free text (150+ variants) not linked to the 17 levers. | Rule-based mapping to lever ids stored on each line (line.lever_ids, reviewable; table line_item_lever). Informational: drives the 'which lines does this lever touch' view, not the math. | none |
| R20 | Company facts | low | Flight attendants 28,000 (baseline Assumptions) vs 27,000 (corporate). | Corporate 27,000 drives the P&L; baseline figure is reference only. | none |
| R21 | Benefits | info | US IT burden 22% of base (baseline labor model) vs corporate benefits load 12.3% of pay (company-wide, calibrated to the 10-K). | Different scopes; both kept. | none |
| R22 | CY28 view | info | Corporate FY2028 is a run-rate bridge on a constant FY2027 base, not a modelled year. | Kept and labelled illustrative (br.*28). | none |
| R23 | Defaults | low | Head start: build.py code says 3 months, final.json and the slider spec say 1. | Slider spec (1) is authoritative. | none |
| R24 | GCC size | info | Fact base cites ~400 GCC staff (Reuters, May 2026); user says ~900. | User figure (already in baseline). | none |
| R25 | Lever library text | low | Lever 12 text mentions a 'depreciation toggle' that no longer exists; lever 5 cites a $405M US pool (now $398M). | Flag for copy cleanup when the library text is shown in the app. | none |
| R26 | Line scaling | medium | Baseline lines were sized at 3,000 / 900 / 800 heads but the lever model drives cost per head from the same pools; changing headcount in one model did not change the other. | Lines carry a scale driver (us / gcc / ctr / none); hc.* changes scale those lines, and pools, unit costs and levers follow. | none at defaults |
| R27 | Addressability | info | Lever 15 uses $31.4M 'partly addressable' platform spend (gross) while the baseline's addressable view weights it at 35% ($11.0M). | Both are right for their use: lever 15 applies its % to the non-locked gross; VP targets use weighted addressable. Derived from the same lines. | none |
| R28 | Labels | info | Rate_Cut_Reality takeaway text cites a ~$138M bar; the current bar is $143.0M. | Text-only; bar is computed. | none |
